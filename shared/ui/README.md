# shared/ui/ —— 共用界面（Vue）

> 阶段 4 启用（目前是占位目录，**没有任何代码被调用**）。
> **阶段 2 的窄屏适配直接在 `renderer/` 上改**，不搬家——避免无意义的文件挪动。

## 放什么

各平台长得一样的那部分界面：

- 页面结构与样式（`.html` / `.css` / Vue 组件或单文件里的模板）
- 交互逻辑（表单校验、结果展示、排行榜、复制按钮…）
- 对宿主的**唯一调用方式**：`window.fgo.*`（36 个方法，见 `contracts/bridge-surface.md`）

## 不放什么

- ❌ 平台专属的外壳：窗口控制、系统菜单、文件对话框、自更新入口、安装引导
- ❌ 直接访问平台能力（`require` / `fs` / `ipcRenderer` / `navigator.clipboard` 直连…）
- ❌ 直接起引擎子进程（走 `shared/engine/` 接口，由平台层决定怎么跑）

## 为什么现在不搬

`renderer/app.js` 约 4150 行，是**纯网页代码**（实测零 Electron 依赖），
现在把它挪进 `shared/ui/` 只带来 diff 噪音、不带来任何能力。
等阶段 4 真要跑第二个宿主时再搬——那时搬完立刻能被两个宿主验证，风险最低。

## 阶段 2 要处理的（与搬家无关）

- 三档断点：大屏（现在的样子）/ 平板 / 手机（两列或纵向卡片）
- 鼠标悬停 → 点击展开（触屏没有 hover）
- 结果长列表懒加载、按钮加大到手指能点
- 横竖屏自适应
