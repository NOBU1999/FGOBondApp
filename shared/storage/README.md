# shared/storage/ —— 数据存取接口（只定接口，不做实现）

> 阶段 1 启用（目前是占位目录，**没有任何代码被调用**）。

## 为什么要有这一层

同一套业务逻辑，桌面端存 **SQLite 文件**，网页 / 安卓存 **浏览器本地库或原生 SQLite**。
如果业务逻辑直接写 SQL 或直接读文件，就搬不过去了。
所以这里只放**接口定义**（要做哪几件事），实现放各平台：

```
shared/storage/           ← 接口（本目录）
platforms/win/...         ← better-sqlite3 / node:sqlite 实现
platforms/web/...         ← IndexedDB / OPFS 实现（阶段 4）
platforms/android/...     ← 原生 SQLite 实现（阶段 5）
python-engine/engine/database.py  ← 引擎侧的只读实现（现成，阶段 1 归位）
```

## 接口分两组（初步划分，阶段 1 细化）

**A. 静态游戏数据（只读）** —— 从者、礼装、特性、阶段特性、活动加成、灵衣名
- 语义：只查不改；由随包数据提供；引擎与界面都要用。

**B. 个人数据（读写，按账号隔离）** —— 账号、Box、排除名单、队伍、自定义礼装、设置（区服等）
- 语义：所有读写都带 `accountId`（队伍 / 自定义礼装例外，见阶段 1 实测）；
- 需要事务的地方（如"复制账号"）由实现保证原子性。

## 硬性要求

1. 接口方法**只能是异步**（浏览器侧必然是异步；桌面侧用同步实现包一层 Promise 即可）。
2. 入参出参**必须是可 JSON 序列化的普通对象**（不许传 SQLite 语句、游标、行对象）。
3. 不许把 SQL 语句泄漏到接口外面（业务层只说"要什么"，不说"怎么查"）。
4. 引擎侧（Python）只需要 A 组 + 只读访问，保持现状即可。
