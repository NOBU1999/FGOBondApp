# Task 4 前端 UI 开发说明

> 最新 UI 已按“6 槽位队伍构建”方案实现，结果在同一页面下方滚动查看。

## 技术选择

- Vue 3（global build，免打包/免构建）
- 本地文件引入：`renderer/vendor/vue.global.prod.js`
- 全部 UI 逻辑在 `renderer/app.js`

## 文件

```
renderer/
├── index.html
├── style.css
├── vendor/vue.global.prod.js
└── app.js
```

## 页面结构

- 顶部工具栏：标题 + Box管理 + 队伍配置
- 主区域：6 个槽位（每列 = 上从者格 + 下礼装格）
- 底部信息栏：Cost / 固定 / 自由 / 助战统计
- 底部操作栏：
  - 清空队伍
  - 随机填充自由位
  - 保存队伍
  - 加载预设
  - 开始计算
- 结果区域：主页面下方，滚轮下滑查看 Top 20

## 交互模型（已确认）

- 用户主动填写的从者/礼装 = 固定（红色荧光 + 🔒）
- 空槽位 = 自由，算法自动填充
- 助战是独立状态，橙色标签，且同一时间只能有一个
- 清空从者格 = 从者 + 对应礼装一起清空
- 清空礼装格 = 只清空礼装
- 右键菜单：设为/取消助战、更换、清空
- 从者格为空时礼装格不可选
- 个人加成 UI 显示百分比，传给引擎前除以 100

## Box 管理

- 持有勾选
- 灵基阶段下拉
- 满绊标记 + 开关一 + 开关二联动
- 个人加成
- 批量设置个人加成
- 搜索/职阶/持有/满绊筛选
- 恢复 Box 默认（二次确认）

## 礼装规则

- 只分两类：
  - 牵绊礼装
  - 其他礼装
- “其他礼装”不按战斗用途细分，只显示稀有度与 Cost
- 牵绊礼装默认过滤：
  - 活动限定礼装不显示
  - 满破 2.5% 及以下低价值礼装不显示

## 数据持久化

- Box 配置保存到 `user_box`
- 队伍预设保存到 `user_teams`

## 运行

开发态：

```bash
npm start
```

加载 `renderer/index.html`，无需 Vite/Webpack。
